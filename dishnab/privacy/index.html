Privacy

Effective/Last updated: November 22, 2026

These pages are for the DishNab app. They are not the Pawprint Log policy.

No account, ads, or tracking

DishNab has no account and no login. It does not include an analytics SDK, show ads, or track you. It does not use App Tracking Transparency, push notifications, RevenueCat, or Firebase. Nothing is sold or shared for advertising. Counts the app keeps for its own parsing stay on the phone.

Social imports

For a public TikTok, Instagram, or Facebook post, the app sends the post URL to a DishNab Cloudflare Worker proxy at https://dishnab-proxy.noushadvali-q01ycx.workers.dev. The request also includes a random install id, the app version, and a page-fallback flag.

The install id is a random UUID stored on the phone. It is not your Apple ID. It is used only for rate limiting.

The worker fetches the public post and returns the caption and metadata, such as the creator and a thumbnail address. It does not store the URL or the caption. It uses the install id and the connection’s IP address to apply a rate limit. That limit is held in memory for the running worker, not in a saved database.

The worker’s application log records only the route, status, time taken, platform, source, and error. Cloudflare, as the infrastructure provider, may keep its usual operational request logs. How Cloudflare handles those logs is described in the Cloudflare privacy policy.

A short link to one of those posts is opened by the phone first, so the app can find the public post URL it sends. If a thumbnail address comes back, the phone loads that image from the site that hosts it. DishNab is not TikTok, Instagram, or Facebook. An import can fail or come back incomplete.

Website imports

For a normal recipe page, the phone fetches the page directly from the site you pasted. That page is not sent to the proxy. A photo on the page, if the recipe has one, is also loaded by the phone from that site. A short link to a website is opened by the phone first, and the page itself is still fetched by the phone.

Feature config

The app fetches a public config file from GitHub to turn features on or off. The request does not include an account, the install id, or any other identifier of you. GitHub receives it as an ordinary web request.

Photos

You can take a picture with the camera or choose a photo. Apple’s Vision reads the text on the phone. The picture is not uploaded to DishNab or to a recognition service. A photo you save with the recipe is stored with that recipe, in the place described below.

Reading the recipe text

On iOS 26 or later, when Apple Intelligence is available, Apple’s Foundation Models may read a caption or a page on the phone. Otherwise a parser on the phone does that work. A recipe you type stays in the app. Recipe text is not sent to any DishNab cloud AI.

Meal plan and grocery list

The weekly meal plan and the grocery list are stored with your recipes, in the same place described below.

Where recipes are stored

Recipes, folders, grocery items, meal plans, and import jobs are stored in your private iCloud when that store can be opened. The container is iCloud.com.noushadvali.dishnab, in CloudKit’s private database. The developer cannot read your private iCloud data.

If that store cannot be opened, those items stay on the phone. If the phone store cannot be opened either, they are held only in memory for this visit, and the app shows: “Recipes will not be kept after you leave the app.”

Signing in to iCloud does not by itself mean a sync has finished. If you use Apple’s iCloud Backup for the whole phone, that is Apple’s service. See Apple’s privacy policy.

The count of social imports for the calendar month is stored on the phone and copied to your iCloud Key-Value Store.

Backup file

Export and import are started by you. Export writes a JSON file on your device. You choose where it goes, such as Files, Mail, or AirDrop. DishNab does not receive it. Anyone you share it with can read it.

The file includes your recipes, folders, meal plans, and whether a recipe is still waiting to be filed. A recipe can include its ingredients, steps, notes, source link, and an optional photo.

It does not include grocery items, import jobs, the social-import count, or a purchase.

Import checks the file before it adds anything. It does not delete recipes you already have. It skips a recipe with the same id or the same link. Meal plans in the file are added with that import.

Purchases

Pro is an optional one-time, non-consumable purchase through Apple’s StoreKit. There is no subscription. Apple shows the price and handles payment. DishNab does not send your receipt to a DishNab server, and it does not receive your card number. Apple’s side of the purchase is covered by Apple’s privacy policy.

Permissions

DishNab asks only for the camera and for photos. Both are used only to read a recipe from a picture you take or choose.

Children

DishNab is not directed to children under 13. It does not ask for a date of birth, and it has no account. A parent can delete the app and delete its iCloud data, as described below.

Deleting your data

Delete the DishNab app to remove what is stored only on that phone. Data already in your private iCloud is removed by deleting DishNab’s iCloud data in iOS Settings, under your name and iCloud. Deleting the app does not by itself delete data already in iCloud.
